バーガーキュー

制作時の課題と工夫

課題：車同士の自然な間隔制御

車が前の車にめり込む、または不自然に停止する問題が発生した。

解決方法：Raycastによる前方検知

BoxColliderの先端からRayを飛ばし、前方に車が存在するかを判定。 条件に応じて移動を制御することで自然な車列を実現した。

課題：食材の重なり管理

バンズや皿に具材を重ねる際、位置ずれや重複登録が発生した。

解決方法：リスト管理とオフセット計算

具材をListで管理し、追加時にオフセットを計算して配置。 同一具材の重複チェックも行い、整った見た目を維持した。

課題：営業フェーズの状態管理

準備中と営業中で処理内容が異なるため、状態遷移の管理が必要だった。

解決方法：enumによるフェーズ管理

Salesの状態をenumで定義し、ボタン操作で明確に切り替える構造にした。 日数や来客数の増加処理も一元管理できるよう整理した。

本制作を通して得た学び

3D空間でのオブジェクト管理や当たり判定制御を通して、 状態管理と責務分離の重要性を再認識した。 また、複数システムが連携する構造設計について理解を深めることができた。

ソードディフェンダー

制作時の課題と工夫

課題：UI Toolkitの要素が直接編集できず、構造理解に苦戦したこと

UI Builder上ではスライダーやタブの一部要素がグレーアウトしており、 従来のUGUIのように直感的な編集ができなかった。 そのため、どのように見た目を変更すべきか理解するまでに時間を要した。

解決方法：USSによるスタイル制御と要素構造の把握

UI ToolkitはUSSでスタイルを制御する設計であることを理解し、 要素の階層構造を確認しながらクラスを定義してスタイルを適用した。 内部構造を把握した上で必要な要素に対してUSSを適用することで、 意図したデザインに調整できるようになった。

課題：UIとゲーム内データの整合性維持

レベルやコインなどの値をUI上で変更する際、 表示と内部データが不整合を起こさない仕組みが必要だった。

解決方法：ScriptableObjectとデータバインディングの活用

UIで扱う数値をScriptableObjectで一元管理し、 データバインディングによってUIとデータを連動させた。 これにより、表示と内部ロジックを分離しつつ、 安全に値を更新できる構造を構築した。

課題：ボタン操作時のフィードバック不足

標準状態のボタンでは押下時の変化が小さく、 操作している実感が弱いという課題があった。

解決方法：USSで押下時スタイルを定義

ボタン専用のクラスをUSSで定義し、押下時のみサイズを拡大するスタイルを適用。 視覚的な変化を加えることで、操作感とUI全体の完成度を向上させた。

本制作を通して得た学び

UI ToolkitはUGUIとは設計思想が異なり、 スタイル（USS）とロジックを分離して管理することが重要であると学んだ。 要素構造を理解した上でスタイルを適用することで、 再利用性と拡張性の高いUI設計が可能になると実感した。

WAVEブレイカー（チーム制作）

制作時の課題と工夫

課題：敵の行動分岐が複雑化し、可読性が低下した

攻撃条件や追跡条件、被弾処理などを個別のif文で管理していたため、処理の追加や調整を行うたびに条件分岐が増えていきました。
その結果、挙動の把握が難しくなり、意図しない状態遷移が発生することがありました。

解決方法：ステートパターンを導入し、状態ごとに処理を分離

Idle・Chase・Attack・Hit・Dieの5つのステートをenumで定義し、 ChangeState()によって遷移を管理しました。
また、stateEnterフラグを用いて「状態に入った瞬間のみ実行する処理」を分離しました。
これにより処理の見通しが良くなり、挙動の追加や修正を安全に行えるようになりました。

課題：Wave進行に伴う難易度設計のバランス調整

敵数のみを増やす設計では、後半に敵を1発で倒せてしまい、攻撃力を強化しても戦闘結果が変わらない状況が発生しました。
そのため、強化要素が機能し続ける難易度設計が課題となりました。

解決方法：Wave数に応じたステータス補正とボス出現の導入

Wave数に応じて敵のHP・攻撃力に段階的な補正を加えました。
これにより後半でも強化が有効に機能する設計とし、 さらにボス出現でゲーム体験に緩急を持たせました。

課題：敵全滅後の進行管理が分散していた

敵がいなくなったタイミングの判定や強化フェーズへの遷移処理が 複数のスクリプトに分散しており、進行フローが把握しづらい状態でした。

解決方法：GameManagerでWave進行を一元管理

敵生成時にListへ追加し、死亡時に削除する仕組みに統一しました。
現在の敵数を管理し、全滅時にアップグレードフェーズへ遷移する構造に整理しました。
これにより「戦闘 → 強化 → 次Wave」というループ構造を明確化しました。

本制作を通して得た学び

ステートによって敵の行動を整理することで、 責務を分離した設計の重要性を学んだ。 また、チーム制作を通してGitによるソース管理や 役割分担の大切さを実践的に学ぶことができた。
